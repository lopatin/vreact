# Fresh audit, November 2026

An adversarial audit of the vreact tool (translator `src/`, Lean model and automation
`lean/`, synth, CLI and report) after round 4, with the goal of soundness: vreact must never
report VERIFIED for code whose JS/React 18 behaviour breaks a stated contract or invariant.

## How it ran

* **Audit rounds.** Each round had 14 lens attackers: names, JSX, state, effects, numbers,
  Map/Set, contracts, Lean trusted base, report, project, synth, coverage, runtime and combinations.
  Every attacker built minimal VTS projects against a frozen copy of the tool at 0b749e2. Two
  independent skeptics reproduced each finding, and a third settled a split. A finding counts only
  if it reproduced. Round 2 was told everything round 1 found.
  * Round 1: 54 confirmed findings.
  * Round 2: 41 more confirmed, plus 2 judged documented limitations and 1 refuted.
* **Fixes.** Each cluster of findings was fixed in its own worktree, with regression cases
  `tests/cases/Fa<Cluster>…`. An independent agent then attacked every fix, the fixer repaired
  what the attack confirmed, and the attack ran again (up to 3 attacks).
* **Stopped early.** The work stopped before the audit ran dry, to save tokens. No round 3
  was run, so the audit is **not** exhausted: round 2 still found 41 new defects. Some
  in-flight work was also lost when the session's scratch directory was wiped:
  * five round-2 fix clusters that had no commit yet;
  * several second-round repairs;
  * the last attack rounds.

  Everything committed was merged here and gated. The "Not fixed" and "Open attack findings"
  sections below are the remaining work.

## What was fixed (by cluster)

### Round 1 (all 54 fixed)

* **implies:** in contracts that run, `implies(a, b)` no longer guards `b` by `a`, because JS evaluates `b` anyway.
* **keys:** distinct keys are enforced among an element's static children, compared as strings.
* **select:** `<select>`/`<optgroup>`/`<option>` content is restricted, so `onChange` comes from the select's own change event only.
* **cbreq:** `callbackRequires` binds its callback by binding, not by spelling. Its lambda is a contract, and every translated contract and constant is closure-checked.
* **deps:** dependency checks compare data paths. A method reference is never a dependency. Effects may list functions and outside values.
* **project:** layouts are rejected where the bundler would run or compile other files: `#`/`?`/`%` in specifiers, symlinks, tsconfig `references`/`extends`, `src` outside the root, the `browser` field. `out` can no longer delete sources, and heartbeats are validated.
* **names:** generated Lean names no longer collide, the Base module is handled correctly, and tuple types are fixed.
* **compenv:** closures, timer callbacks and initial values see exactly the locals JS gives them. State and invariants respect declaration order (TDZ), and local recursion is rejected.
* **numbers:** int/number mixing, literal typing, relative `with()`, closed facts and nullish messages.
* **report:** results are attributed by module identity, unimported proof files are rejected, and proof imports are read as Lean reads them. Dotted proof file names are rejected.
* **runtime:** effects with a dependency array re-run in the model, and remounts and StrictMode's double effect run are modelled.
* **synth:** holes in contracts are never filled. Top-level code, helper sorries and time limits are handled, along with type imports and quoted fields.

### Round 2 (fixed)

* **recursion:** self-recursive components are rejected, and an elaboration error never counts as a failure of a user obligation.
* **forms:**
  * Defaults, rest elements and extra elements in `useState`/`useReducer` destructuring are rejected.
  * `var`/`let` hook declarations are rejected. This also closes a critical regression the compenv fix had introduced: a `var` redeclaring a setter.
  * A hook in a non-first declarator is rejected.
  * Optional and rest named tuple members are rejected.
* **stmts:** switch case labels grouped with `default` are translated, as are default-only switches. An effect after a branching block is emitted once.
* **dom:**
  * spec's test hook moved under a symbol, so named access cannot clobber it.
  * `name`/`id` values that DOM named access would turn into a property react-dom reads are rejected.
  * autoFocus focus chains are rejected.
  * `createRoot` is stated as a trusted assumption.
* **rejections:** namespace-import members, `return undefined;` in effects, updating helpers called for their value, and callbacks with fewer parameters are accepted, and the remaining rejection messages are true.
* **facts:** module-level facts are checked by evaluation over every `@opaque` constant, and a hole in an invariant is reported as blocked.
* **tdz:** covered by the compenv repair: state and invariants respect declaration order.
* **projfiles:**
  * A declaration file passes as the standard library only from TypeScript's own lib directory (project-r2-1, critical).
  * `include` takes `.ts`/`.tsx` files only, so allowJs JSDoc casts are out (project-r2-3).
  * vreact.json shapes are validated.

## Not fixed

These are listed with reasons. Each is a starting point for the next round.

* **project-r2-2** (unsound, high; the skeptics judged it a documented limitation):
  `/// <reference types="./node_modules/x" />` brings a project `.d.ts` in as an external
  library. Next step: reject `types` references that resolve inside the project, or document
  the exact rule.
* **effects-r2-1** (unsound, medium): console format specifiers (`%d`/`%s`/…) convert a record
  argument through its `toString`/`valueOf` field. Next step: reject format strings with
  specifiers when an argument may be a record.
* **lean-r2-2** (unsound, low): `range(n)` is modelled as total, but JS throws RangeError for
  `n >= 2^32`. Next step: add an obligation `n < 2^32`, or document it beside the 2^53 caveat.
* **numbers-r2-1 / numbers-r2-2** (crash): an operand obligation under `Math.floor`/`Math.trunc`
  of a number division, or under `.includes` inside a contract, is missing from the Lean term.
* **numbers-r2-3** (spurious rejection): string properties and methods on a string-literal enum value.
* **coverage-r2-3 / combo-r2-1** (spurious failure): the key function of a keyed list lacks the
  `x ∈ xs` hypothesis.
* **report-r2-1..4:** comments in proof-file headers. The report and names repairs now read
  proof imports with Lean's parser and a Lean-faithful tokenizer, and reject any header the two
  read differently. This very likely fixes r2-1..3 (hidden imports, the incremental key, the
  cycle check), but nobody re-ran those repros. r2-4, comment text read as a `namespace` command
  by the namespace check, is unverified.
* **synth-r2-2** (synth bug): `synth --write` can write a fill that breaks another function.
  **synth-r2-1** (spurious rejection): synth refuses to start under noUnused* when only the
  missing fill would use a parameter.

## Open attack findings on the fixes

Attacks the fixers had not yet answered when the work stopped:

* **project (high):** a `jsxImportSource` bypass through tsconfig's `${configDir}` token plus a
  quote in the project directory name.
* **project (medium):** an object `"browser"` field in *any* ancestor package.json is rejected,
  even where Vite never applies it (spurious rejection).
* **keys (medium):**
  * many conditional keyed siblings plus one dynamic key time out (an exponential case split in `unique-keys`);
  * a `number`-typed key next to another keyed sibling can never be proved;
  * no case pins the key of a JSX const rendered under a condition.
* **facts (medium):** facts whose guard bounds an index through an accessor or alias of an
  `@opaque` constant no longer verify. A function call or alias still hides a constant from
  evaluation, constants are unfolded only one level, and the docs overstate "by evaluation".
* **runtime (low):** the model forces a remount where React 18 keeps the instance, for a single
  child that toggles between `<><Child/></>` and `<Child/>`. React's run, with the state kept,
  is then not a run of the model. **This needs a check for soundness.**
* **names (low):**
  * the upstream cycle drop misses View/Posts imports and letter-case variants on case-insensitive disks;
  * renaming `_`-prefixed modules disconnects their lemma files.
* **numbers (low):**
  * `xs.with(-k, v)` with `k <= 0` no longer verifies;
  * translation time grows exponentially with nested conditionals and array literals;
  * some TS-typed joins are still rejected;
  * a `| null` message shows for `| undefined` in one path;
  * the `decide` fallback can confirm a false `String()` fact beyond 2^53, which rests on the documented caveat.
* **deps, implies (low):** a wrong `useCallback` named in nested dependency rejections, and weak tests and docs nits.
* **Repaired, but not re-attacked:**
  * the second synth repair, which answers all 7 synth attack findings: ES bindings in the harness, exported bindings, multi-hole sorries, the 5 s cap, lazy enumeration, contract-only predicates;
  * the dom repair, which narrowed the autoFocus and named-access rules;
  * the stmts and rejections fixes;
  * the project-files and forms changes made at the end.
